# Localtunnel Known Issues

## Random Password Protection

### The Problem

When you create a tunnel through this app, you may encounter a **password prompt** when accessing the tunnel URL. This looks like HTTP Basic Authentication asking for a username and password.

**Example:**
```
https://afraid-socks-behave.loca.lt/
```
Prompts for: "Please enter a valid IPv4 or IPv6 address"

### Why This Happens

This password protection is **NOT** controlled by our application. It is a security feature built into the free localtunnel.me service to prevent abuse.

From the localtunnel documentation and source code:
- Localtunnel.me servers may randomly add HTTP Basic Authentication to tunnels
- This is done server-side and cannot be controlled by clients
- The password is randomly generated by localtunnel's servers
- **You cannot predict or control when this will happen**

### What You're Actually Seeing

The password prompt is from **localtunnel.me's servers**, not from:
- Our auth profiles feature (which isn't implemented yet anyway)
- Your local application
- Any configuration you set

### Why The Error Message is Confusing

The error message "Please enter a valid IPv4 or IPv6 address" is misleading. This is actually the **username field** being validated - localtunnel sometimes expects an IP address as the username for their anti-abuse system.

### Solutions and Workarounds

#### Option 1: Use Custom Subdomains (Recommended)
Custom subdomains are less likely to get password-protected:
```
Subdomain: my-unique-app-name
URL: https://my-unique-app-name.loca.lt/
```

#### Option 2: Create a New Tunnel
Simply delete the current tunnel and create a new one. The new URL might not have password protection.

#### Option 3: Use Alternative Tunneling Services
If you need reliable, password-free tunneling, consider:
- **ngrok** (free tier available, more reliable)
- **Cloudflare Tunnel** (free, very reliable)
- **Tailscale Funnel** (free, requires Tailscale)
- **Serveo** (free, SSH-based)

#### Option 4: Self-Host Localtunnel Server
You can run your own localtunnel server which won't have this restriction:
```bash
npm install -g localtunnel-server
lt-server --port 8080
```

Then modify the app to use your custom server instead of localtunnel.me

### Why We Can't Fix This

The password protection is implemented at the localtunnel.me server level, not in the client library. Our application uses the `localtunnel` npm package which connects to localtunnel.me's public servers.

To quote from localtunnel's GitHub issues:
> "The password protection is added by the server to prevent abuse of the free service. This is not configurable from the client side."

### When Will Our Auth Profiles Work?

Our auth profiles feature (visible in the UI but marked as "Coming Soon") is different:
- It will add authentication **before** the request reaches localtunnel
- It requires implementing a local HTTP proxy
- It will be under our control
- It's planned for a future release

### Debugging Tips

If you want to check if a tunnel has password protection:

1. **Check the logs** - Click the "Logs" button on your tunnel
2. **Look for the URL** - The initial URL doesn't indicate if auth will be added
3. **Test in private browsing** - This rules out cached credentials
4. **Try curl**:
   ```bash
   curl -I https://your-tunnel.loca.lt/
   ```
   If you see `401 Unauthorized` or `WWW-Authenticate: Basic`, it has password protection.
